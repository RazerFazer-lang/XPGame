# XPGame

XPGame is a cooperative 2D horde-survival browser game with an authoritative Colyseus multiplayer server.

## One-click multiplayer

Open the repository directly in GitHub Codespaces:

https://codespaces.new/RazerFazer-lang/XPGame?quickstart=1

The included devcontainer installs dependencies, builds the production client and starts the combined game + multiplayer server on port `3000`. GitHub can forward that port as a browser URL. The forwarded URL is generated by GitHub and only remains available while the Codespace/server is running.

## Stack

- TypeScript
- Phaser 4
- Node.js
- Colyseus
- Vite

## Start locally

```bash
npm install
npm run dev
```

For the production-style single-port server:

```bash
npm run build
npm start
```

Then open `http://localhost:3000`.

## Multiplayer

The game supports up to four players in an authoritative Colyseus room. The browser client supports quick matchmaking plus direct room-code joining, lobby ready state, map and weapon selection, reconnect cleanup, server-authoritative movement, mouse aim and server-side fire cooldowns.

All gameplay messages are validated on the server. Invalid payloads, non-finite
coordinates, unsupported weapons/maps, and over-capacity entity creation are
ignored without changing authoritative state.

## Gameplay systems

- Downed state, lives, automatic respawn and co-op revive
- Neon City, Desert Ruins, Frozen Outpost and Toxic Swamp maps
- Rifle, Shotgun, SMG, Cannon and Arc weapons
- Stackable level-up upgrades and build stats
- Basic, fast, tank, ranged, swarm, splitter, healer and elite enemies
- Mini-bosses and multi-phase bosses
- XP drops and loot drops
- Coins, weapon levels, score and run leaderboard
- Timed events including Blood Moon, Supply Drop, Overdrive and Blackout
- Boss rage phases and healer enemies
- Local meta statistics and browser-persistent best scores
- Settings for audio and particles
- Procedural combat feedback audio
- Particle feedback and responsive HUD
- Wave scaling and spatial collision partitioning
- GitHub Actions typecheck, test and production build verification

## Room codes

One player can enter a room code under `Room-Code` and use `JOIN ROOM`. The host's current Colyseus room ID is shown in the HUD. `QUICK MATCH` creates or joins the normal `game` room.

## Important persistence note

Run state is authoritative on the game server. Meta statistics currently persist locally in the player's browser via `localStorage`; they are not yet a cross-device cloud account system. A permanent shared leaderboard would require a persistent database or hosted backend in addition to GitHub Codespaces.

## Verification

```bash
npm run typecheck
npm test
npm run build
npm run test:integration
```

`npm run test:integration` starts an isolated server and exercises four real
Colyseus clients, lobby leave/rejoin, malformed messages, active disconnect,
and room-capacity matchmaking. GitHub Actions runs these checks plus a
production health smoke test on pushes and pull requests.

## Troubleshooting

- **Server not starting / port in use:** set `PORT` and optionally `HOST`
  before `npm start` (the default is `0.0.0.0:3000`).
- **Connection or matchmaking error:** verify `GET /health` first, then use
  the same forwarded host and port for the browser client and WebSocket.
- **Room full:** quick matchmaking creates another room once four players
  occupy the current lobby; direct room-code joins must use an open lobby.
- **Codespaces or Hamachi:** forward/expose port 3000 and connect through the
  host's reachable IP rather than `localhost`.
